# Design: native query observability, bounded Phase 5A subset

Read `prd.md` and `research/source-audit.md` first. This design is the approved implementation contract for the active task.

## Boundary and data flow

The existing native host remains the sole owner of parsing, sequence execution, cache, upstreams, and listener I/O. Add one host-owned observer that receives a compact terminal result from the listener. The strict 5A compiler accepts exactly one listener plugin per host: W1 chooses UDP or TCP, while W2/W3 use UDP. Preserve rejection of additional listener plugins, so the sole listener's enable_audit value unambiguously governs detailed capture for every admitted request in that host. The execution driver supplies facts it alone knows (cache lookup result, ordered external attempts, accepted final upstream, response source and failure provenance); the UDP/TCP listener supplies admission time, transport/client identity, framing/send outcome, and cancellation. A terminal guard finalizes once for every admitted request, including early return and shutdown paths. Observing a result must not alter response generation, forwarding, cache publication, or cancellation.

Suggested flow:

```
listener admit/parse -> request context + observer guard
  -> existing sequence/exchange/cache driver -> wire response + execution facts
  -> existing frame/send -> terminal outcome
  -> observer counters + optional bounded audit append
```

Use one lifecycle enum rather than inferring send success from nonempty response bytes. Its mutually exclusive values are transport-send-succeeded, transport-send-failed, canceled, and no-response. Send-succeeded means the existing UDP/TCP transport operation completed successfully; it is not proof that the client received the packet. A non-cancellation transport error is send-failed. Cancellation wins if it prevents successful send completion, including while a send is pending. No-response is a terminal outcome only when execution finishes without a DNS response and cancellation has not already won; a canceled event may separately have response state no-response if execution had not formed a response. Keep response source and upstream-attempt/failure facts in separate fields so they cannot be confused with lifecycle. Count malformed/partial input at the listener before admission; a parse failure does not create a terminal query event. Account for TCP framing and UDP send at the actual existing I/O boundary. Audit duration covers admission through terminalization. Test deterministic terminalization with injected send failure/cancellation, not timing sleeps.

## Stable semantic contracts

The Phase 5A audit record is a typed Rust internal record, not an early promise of the 5C JSON/API wire schema. Its fields are: timestamp, client IP/address, transport, qname/qtype/qclass, elapsed time, lifecycle terminal outcome, response state/source, final DNS rcode when a response exists, cache status, final sequence tag, final upstream identity, ordered upstream attempts with per-attempt outcomes, and failure provenance. Response state is either a DNS response with its rcode and source (cache, upstream identity, or local) or no-response. The final upstream is set only after a qualifying upstream response has become the final DNS response; a W2 hit has no upstream. W3's B leg remains diagnostic when the final answer came from A or C. A local SERVFAIL is rcode SERVFAIL with local response source; an upstream SERVFAIL is the same rcode with upstream source and identity. A timeout remains upstream-timeout failure provenance and an attempt timeout, even when it causes a local SERVFAIL response. None of these execution facts creates a new lifecycle terminal value. Where a field cannot be established, record an explicit absent/unknown value and never guess from configuration.

An admitted request interrupted before execution establishes cache disposition uses `undetermined` instead of `not-applicable`; the metrics snapshot exposes this as `cache_undetermined_total`. If an upstream attempt is in progress when its request is dropped, retain it as an actual attempt with `canceled` or `interrupted` outcome according to the request cancellation scope. Those outcomes contribute to total attempts and have separate bounded per-upstream counters; they are not counted as responses, failures, or timeouts.

The Phase 5A metrics snapshot uses fixed counters and a fixed-bucket duration histogram. It includes the R4 dimensions without qname/client/trace labels. Upstream dimensions are bounded to the strictly compiled catalog. Completed means an admitted query reached any one lifecycle terminal outcome, including cancellation, send failure, or no-response. The disjoint transport-send-succeeded, transport-send-failed, canceled, and no-response counters sum to completed; admitted equals in-flight plus completed; histogram count equals completed. Response-code totals count a formed DNS response once and do not claim client delivery. Forward attempt totals match mock upstream events where a network attempt was actually made; cache hits add no forward attempt. The cumulative histogram uses inclusive upper bounds [50, 100, 250, 500, 1,000, 2,500, 5,000, 10,000, 25,000, 50,000, 100,000, 250,000, 500,000, 1,000,000, 2,500,000] microseconds plus +infinity: an observation contributes to every finite bound greater than or equal to its elapsed duration, and always to +infinity. The snapshot exposes each bound and its cumulative count; +infinity equals completed. Malformed input is not admitted and is excluded from the histogram. Production passes elapsed time from the listener's monotonic clock; the collector entry point also accepts an explicit duration so boundary tests can be deterministic without sleeps. Implement read-only metrics_snapshot and audit_snapshot methods over an Arc-backed observer that is Send + Sync. A short in-memory mutex protects the bounded metric and audit state while recording and copying snapshots, so equations hold during concurrent reads; hold it only for bounded memory work, never DNS, disk, network, or management work. Keep lock overhead inside the Phase 5A regression budget and do not couple the observer API to Rc or a current-thread executor.

Detailed audit is enabled by the sole listener's existing enable_audit flag. For this isolated 5A process, true begins in-memory capture at host startup and false retains no per-query audit records; basic metrics are always updated. Check the flag before materializing or appending sensitive query/client fields. A multi-listener graph, including mixed audit values, remains unsupported and rejected by strict compilation. Use a bounded ring with a default 100,000-record limit and an explicit eviction count, matching the current Go default retention size without reproducing Go's silent queue loss. A test-only host option can lower the limit to exercise eviction. No per-query disk/network I/O, blocking async writer, or unbounded channel is introduced. Store no credentials. Any operational error in capture must be visible in the snapshot rather than silently losing records.

## Compatibility and ownership

- Keep strict YAML grammar, exactly-one-listener enforcement, and plugin-count checks. This task changes only the known enable_audit value acceptance; unsupported syntax and additional listeners must still fail before assembly and socket bind.
- Preserve the current single host runtime and all existing W1/W2/W3 DNS semantics. The observer's read-only snapshots can later feed 5C `/metrics` and audit APIs, but this task does not expose an HTTP endpoint or commit to a JSON schema.
- Keep the Rust-native path independent of Go/cgo adapters. Go source is a field/behavior discovery reference; the Rust observer must not copy silent-loss behavior or Go internals.
- During shutdown, stop admission first, finalize or cancel/join admitted requests, then close upstream owners as today. After drain, in-flight is zero and snapshots are stable. Rebind creates fresh owner state.
- Full audit fields such as response answers/flags, domain-set/group/source metadata, API pagination/ranking/window stats, persistence, capture control, and UI behavior are reserved for 5C. Record enough accurate execution provenance now so future fields do not require a second router.

## Trade-offs and evidence gate

An in-memory snapshot avoids a premature management API and keeps the query path free of disk/network I/O. It is not a user-facing audit UI; Phase 5C owns that contract. A ring retains the most recent events rather than promising unbounded history, with visible eviction accounting. Its lock or synchronization cost must be measured with audit on and off; if the current-thread collector becomes a bottleneck, optimize from profiling evidence without replacing the behavioral contract.

Before implementation, freeze the old Rust source/binary, W1/W2/W3 fixtures, runner hash, offered rates, duration/repetition, affinity/VM topology, validity gates, and latency/throughput/CPU/RSS regression budgets in `research/performance-manifest.md`. Pin the new commit/binary before official Linux candidate runs. Compare old versus new with audit off; compare new audit on versus new audit off, since the old host rejects audit on. The prior report's sender shortfalls and absent overload trigger prohibit using an invalid high-rate stage to excuse or prove overhead. Use only valid low/moderate offered load for this task; a later dedicated profiling/measurement task owns overload discovery and multi-core analysis. Preserve rejected attempts and limitations in the result report. Never test on production `mos`.
